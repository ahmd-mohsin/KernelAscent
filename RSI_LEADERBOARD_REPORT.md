# KernelAscent RSI Leaderboard — Build Report

This document records what we built for the KernelAscent RSI benchmark, why, and how to reproduce it.
It covers the scientific design, the difficulty-standardization method, the distributed infrastructure,
and the current multi-family leaderboard.

Site: https://ahmd-mohsin.github.io/KernelAscent/ · Running record: [`BENCHMARK_LOG.md`](BENCHMARK_LOG.md)

---

## 1. What KernelAscent measures

KernelAscent asks whether models get better at writing GPU kernels. A model writes a kernel. The grader
checks correctness against an fp32 reference and speed against `torch.compile`. There are two tasks.

- **Task 1, Capability.** Can a model write a correct, fast kernel in one shot. Open and closed models compete.
- **Task 2, RSI.** Does self improvement compound. An open weight model trains on its own correct kernels and
  we check whether its held out capability keeps rising. Only open weight models can run this, because self
  improvement here means changing the model's own weights.

Capability is a snapshot. RSI is the slope.

## 2. The problem we solved

Earlier the benchmark tried to detect recursive self improvement with frozen weights, using causal estimators
on an agent that edits its own procedure. That work established a real result. With frozen weights the
compounding term is structurally near zero, because the improver cannot improve itself. The fix is to let the
weights change. That is Task 2, the weight level RSI loop.

Then a second problem appeared. A strong model saturates an easy task bank in one shot, so there is no room to
measure compounding, and a flat result is ambiguous. It could mean the model does not compound, or it could
mean the bank had no headroom. We removed that ambiguity with difficulty standardization.

## 3. The RSI loop

Each round, on a fixed task bank split into train and held out sets:

1. The open model writes `k` candidate kernels per train task.
2. The grader keeps the ones that are correct.
3. We LoRA train the model on its own correct kernels.
4. We re score the model on the disjoint held out split, and report `C_r`.

Two controls run alongside.

- **Frozen base.** The same model with no training. Isolates gains from training at all.
- **Round 0 data control.** Retrained every round on the first round's kernels only. This is the strict test.
  It separates genuine self improvement from simply doing more training on old data.

RSI is supported when `C_r` rises and the self trained arm beats both controls.

Grading runs in a crash isolated subprocess, so a kernel that triggers a CUDA device assert cannot poison the
harness. Generation and grading are batched for throughput. LoRA targets adapt across architectures, with an
all-linear fallback for fused QKV models. Training uses fp32 with gradient checkpointing, since bf16 training
collapsed generation on larger models.

## 4. Difficulty standardization, the key method

The RSI bank is filtered against the frozen base model before any training. For each candidate task we sample
the frozen base `k` times and record two numbers.

- `correct_rate`, the fraction of samples that are correct.
- `best_score`, the best of `k` speed resolved score.

We admit a task only when `correct_rate > 0` and `best_score <= 0.75`. In words, the base can sometimes solve
it, so there is a positive example to learn from, but it does not already run fast, so there is room to climb.
This produces a bank where the starting score is deliberately low, every task is hard but learnable, and any
flat result is attributable to the model rather than a saturated bank.

The result is `dataset/kernel_bank/rsi_bank_hard.json`, 50 tasks across tiers L1 memory and reduction, L2
matmul with epilogue, and L3 attention and normalization. Frozen base floor is about 0.43 to 0.52.

## 5. Infrastructure

- **Task curation.** All task content is generated by Fable 5.1 and GPU validated. The curator hangs on open
  ended prompts for hard attention kernels, so L3 uses concrete single op specs with a short timeout and retry.
- **Difficulty filter.** `difficulty_filter.py` runs the frozen base over a large candidate set and keeps the
  hard but learnable band.
- **Batched execution.** `lab_weight_rsi.py` batches generation across tasks and grades in chunks, which cut a
  round from about 80 minutes to about 20 to 30 minutes for a 7B model.
- **Distributed run.** The leaderboard runs across three Greenland p4d instances, nine nodes, 72 A100 40GB
  GPUs. Each node is bootstrapped with the code, the bank, and pinned dependencies. Small models take one GPU
  per arm. Models of 6.7B and up shard two GPUs per arm. A per node collector pulls each model's result JSON
  and an aggregator builds the board.

## 6. The leaderboard

Open models across nine families run the same standardized loop for five rounds. Families include Qwen coder
and general, DeepSeek Coder, Yi Coder, Phi, SmolLM, OpenCoder, StableCode, Llama, and Gemma, spanning 0.5B to
14B. The board is live and data driven at `docs/data/rsi_leaderboard.json`, rendered as a sortable table and an
animated bar chart. Capability uses `docs/data/leaderboard.json` the same way.

Columns are C0 the frozen base score, peak and final held out score, delta versus frozen, self minus control,
and a verdict of compounds, gains, flat, or overfits.

## 7. Findings

The board shows a clear scale and family crossover.

- Small models start low on the hard bank and gain a lot from self training. Several, including DeepSeek Coder
  1.3B, Llama 3.2 3B, and Qwen Coder 1.5B, keep pulling ahead of the round 0 control, which is genuine compounding.
- Very small models such as Llama 3.2 1B stay flat, because they never write a correct kernel to learn from.
- A strong 7B overfits. It keeps solving the train tasks while its held out score falls.

The takeaway is that naive rejection sampling self training helps models that have headroom and a positive
signal, and hurts strong models that narrow onto their own outputs. The RSI score behaves like a thermometer.
It reads near zero or negative when a model does not compound, and clearly positive when it does.

## 8. Reproduce

```bash
# build the standardized RSI bank from a curated candidate set
python3 kernelascent/v3/difficulty_filter.py --model Qwen/Qwen2.5-Coder-7B-Instruct \
  --in kernel_bank/hard_all.json --out kernel_bank/rsi_bank_hard.json --k 8 --keep-hi 0.75

# run the RSI loop for one open model
python3 kernelascent/v3/lab_weight_rsi.py --model <hf-id> --rounds 5 --k 3 --n-train 20
```

## 9. Planned, Task 3, teacher RSI

A third task will let closed models participate in the RSI axis as teachers. A closed model writes kernels,
an open model trains on the correct ones, and we measure the open model's held out gain against the same two
controls. A closed model cannot change its own weights, but it can raise another model's. This tests whether a
stronger teacher produces a better student than the student teaching itself. It will be built after Capability
and self RSI are complete.
